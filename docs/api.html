Полный справочник API

Rust embedding, расширения команд, runtime, IPC, конфигурация, модели, аудио и всё необходимое для создания приложения поверх ядра.

Этот документ описывает публичный контракт assistant-core 1.3.0: встраивание runtime, расширения команд, адаптеры, конфигурацию, IPC, события, модели, аудио, метрики и диагностические приложения. Точные сигнатуры доступны в Rustdoc.

Раздел 1

Версии, Cargo features и платформы

  • CORE_API_VERSION = 3 — версия публичного Rust extension/embedding API.
  • PROTOCOL_VERSION = 4 — несовместимая граница wire-протокола IPC.
  • CURRENT_CONFIG_VERSION = 4 — схема TOML и CoreConfig.
  • Основная платформа — Windows 10/11 x64, MSRV — Rust 1.97.
  • default feature model-source-huggingface включает установку модели.
  • feature stt-sherpa-onnx включает SherpaOnnxRecognizer и wake-word API.
toml
[dependencies]
assistant-core = { git = "https://github.com/BYxarek/voice-assistant-core", tag = "v1.3.0", features = ["stt-sherpa-onnx"] }
tokio = { version = "1", features = ["macros", "rt-multi-thread"] }

Ломающий Rust-контракт требует увеличения major-версии crate и CORE_API_VERSION. Несовместимый JSON/framing требует новой PROTOCOL_VERSION. Добавление необязательного поля Serde или нового запроса, который старый клиент не отправляет, допускается внутри protocol v4.

Раздел 3

Рекомендуемое встраивание runtime

Приложение создаёт:

  1. проверенный CoreConfig;
  2. Arc<dyn SpeechRecognizer>;
  3. CommandRegistry;
  4. HandlerRegistry как Arc<dyn CommandExecutor>;
  5. Runtime, затем spawn_runtime_service.
rust
use std::{sync::Arc, time::Duration};
use assistant_core::{
    CommandRegistry, CoreConfig, CoreMetrics, MockRecognizer, Runtime,
    RuntimeComponents, builtin_handlers, spawn_runtime_service,
};

# async fn example() -> Result<(), Box<dyn std::error::Error>> {
let config = CoreConfig::bundled_example()?;
let handlers = builtin_handlers(&config.commands)?;
config.validate_with_handlers(&handlers)?;

let metrics = CoreMetrics::default();
let runtime = Runtime::new(
    Arc::new(MockRecognizer { text: "открой блокнот".into() }),
    CommandRegistry::new(config.commands.clone(), config.matching.normalize_yo),
    Arc::new(handlers),
    config.wake_word.keyword.clone(),
    config.policy.clone(),
    Duration::from_millis(config.inference.timeout_ms),
    Duration::from_millis(config.wake_word.cooldown_ms),
    metrics,
);
let (handle, task) = spawn_runtime_service(runtime, 32)?;
handle.begin_capture().await?;
// После завершения VAD: handle.captured_audio(request).await?;
handle.shutdown().await?;
task.join().await?;
# Ok(()) }

RuntimeTask::join ждёт завершения, abort_handle применяется только как последний bounded shutdown fallback. Capacity spawn_runtime_service должна быть больше нуля.

Runtime доступен напрямую для тестов и однопоточного embedding. В этом случае вызывающая сторона сама должна вызывать expire_confirmation, complete_cooldown и не выполнять методы параллельно.

AssistantState::can_transition_to — нормативная таблица переходов. Shutdown разрешён из любого состояния, кроме уже завершённого. Сбой STT/handler публикует RecoverableError и возвращает runtime к listening, если переход допустим.

let current = AssistantState::IdleListening;
let next = AssistantState::SpeechDetected;
if !current.can_transition_to(next) {
    return Err(format!("недопустимый переход: {current:?} -> {next:?}"));
}
Раздел 5

События

AssistantEvent сериализуется с полем type в snake_case:

  • state_changed { previous, current };
  • transcript_ready { text, confidence };
  • audio_level { rms };
  • transcript_unavailable { reason };
  • command_matched { command_id };
  • command_started { command_id };
  • confirmation_required { command_id, confirmation_id };
  • confirmation_cancelled { command_id, confirmation_id, reason };
  • command_finished { command_id, result };
  • command_not_matched { text };
  • recoverable_error { component, message };
  • audio_device_changed { device };
  • audio_device_fallback { requested_device_id, device };
  • model_install_progress { completed_files, total_files, file };
  • model_ready { revision }.

Причины отсутствия транскрипта: wake_word_not_detected, too_short, silence, model_unavailable. Причины отмены: user, expired, recovery, suspended, reconfigured. События предназначены для UI и наблюдения; GetStatus, GetHealth, GetModelStatus и GetMetrics являются источником текущего durable state после переподключения.

rust
use assistant_core::AssistantEvent;

let mut events = handle.subscribe();
while let Ok(event) = events.recv().await {
    match event {
        AssistantEvent::TranscriptReady { text, .. } => println!("{text}"),
        AssistantEvent::ConfirmationRequired { confirmation_id, .. } => {
            // Покажите диалог и передайте этот одноразовый token в handle.confirm(...).
            println!("нужно подтверждение: {confirmation_id}");
        }
        AssistantEvent::RecoverableError { component, message } => {
            eprintln!("{component}: {message}");
        }
        _ => {}
    }
}
Раздел 6

Extension API команд

Новая команда не требует изменения ядра. Приложение реализует CommandHandler, объявляет HandlerSchema, регистрирует handler и добавляет CommandConfig.

rust
use std::sync::Arc;
use async_trait::async_trait;
use assistant_core::{
    CommandHandler, CommandParameters, CommandResult, CoreError,
    HandlerRegistry, HandlerSchema,
};

struct SetVolume;

#[async_trait]
impl CommandHandler for SetVolume {
    fn schema(&self) -> HandlerSchema {
        HandlerSchema::new("set_volume", ["level"], ["device"])
    }

    async fn execute(
        &self,
        parameters: &CommandParameters,
    ) -> Result<CommandResult, CoreError> {
        let level: u8 = parameters["level"]
            .parse()
            .map_err(|_| CoreError::Command("level must be 0..=100".into()))?;
        if level > 100 {
            return Err(CoreError::Command("level must be 0..=100".into()));
        }
        Ok(CommandResult { message: format!("volume={level}") })
    }
}

let mut handlers = HandlerRegistry::new();
handlers.register(Arc::new(SetVolume))?;
# Ok::<(), CoreError>(())

Правила:

  • handler name непустой и содержит только ASCII lowercase и _;
  • имена уникальны;
  • required/optional parameter sets не пересекаются;
  • неизвестные, пустые и отсутствующие параметры отклоняются;
  • внутренние параметры с _ не входят в публичную schema;
  • runtime добавляет _command_id, чтобы built-in allowlist мог связать вызов с проверенной командой;
  • каждый handler ограничен CommandConfig.timeout_ms;
  • распознанный текст не передаётся handler и никогда не исполняется как shell.

builtin_handlers возвращает stock registry с launch_app. LaunchAppHandler запускает только executable, связанный с enabled command ID. LaunchAppExecutor и общий CommandExecutor сохранены для low-level embedding; для новых расширений используется CommandHandler.

Matching выполняется после normalize: lowercase, удаление пунктуации, схлопывание пробелов и опциональная замена ё → е. Сопоставление строгое: полная фраза либо полная фраза после известного wake-word prefix.

Раздел 7

Адаптеры STT, VAD и KWS

SpeechRecognizer::transcribe(TranscriptionRequest) сохраняет пакетный fallback. Методы begin_stream, push_stream и finish_stream позволяют начать decoding сразу после wake word; recover пересоздаёт поддерживающий это native worker после timeout. Реализация не должна блокировать audio callback.

SherpaOnnxRecognizer::new_for_model(model_dir, model, threads, queue_capacity, metrics):

  • проверяет обязательные ONNX/tokens файлы;
  • создаёт, прогревает и supervises persistent native worker;
  • использует bounded queue;
  • отклоняет пустые, non-finite samples и нулевой sample rate;
  • использует bounded exponential backoff и restart budget после timeout;
  • при threads = 0 выбирает доступный host parallelism.

ModelSpec::mode выбирает online либо offline sherpa-onnx runtime. Offline-модель использует пакетный fallback существующего SpeechRecognizer и не принимает streaming jobs.

rust
use assistant_core::{
    CoreMetrics, SpeechRecognizer, TranscriptionRequest,
    audio::read_wav_mono,
    models::{ModelManager, model_spec},
    stt::SherpaOnnxRecognizer,
};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let model_id = "alphacep/vosk-model-small-ru";
    let models = ModelManager::new(r"C:\VoiceAssistantCore\models");
    let directory = models.resolve(model_id)?;
    let (samples, sample_rate) = read_wav_mono(r"C:\audio\command.wav")?;
    let recognizer = SherpaOnnxRecognizer::new_for_model(
        directory,
        model_spec(model_id)?,
        0,
        2,
        CoreMetrics::default(),
    )?;
    let result = recognizer
        .transcribe(TranscriptionRequest { samples, sample_rate })
        .await?;
    println!("{}", result.text);
    Ok(())
}

UnavailableRecognizer позволяет daemon стартовать без модели. MockRecognizer предназначен для тестов.

VoiceActivityDetector имеет reset и process. EnergyVad сравнивает RMS с threshold. AudioRingBuffer хранит bounded pre-roll. CommandCollector завершает utterance по trailing silence либо hard maximum. CommandAudioPipeline<V> объединяет pre-roll, wake-word gate, VAD и collector; push возвращает Some(Vec<f32>) только для законченной команды.

SherpaWakeWordDetector::new_with_aliases кодирует canonical keyword и aliases в одном detector. process принимает streaming mono frame и возвращает WakeWordDetection { keyword, start_time }; reset очищает decoder state.

rust · VAD pipeline
use assistant_core::signal::{CommandAudioPipeline, EnergyVad};

let sample_rate = 16_000usize;
let mut pipeline = CommandAudioPipeline::new(
    EnergyVad::new(0.015),
    sample_rate * 900 / 1_000,   // pre-roll
    sample_rate * 300 / 1_000,   // minimum command
    sample_rate * 10_000 / 1_000,
    sample_rate * 700 / 1_000,   // trailing silence
);

if let Some(command) = pipeline.push(&frame, wake_word_detected) {
    handle.captured_audio(assistant_core::TranscriptionRequest {
        samples: command,
        sample_rate: sample_rate as u32,
    }).await?;
}
rust · KWS
use assistant_core::{config::CoreConfig, models::{ModelManager, model_spec}};
use assistant_core::wakeword::SherpaWakeWordDetector;

let config = CoreConfig::bundled_example()?;
let model = model_spec(&config.wake_word.model)?;
let directory = ModelManager::new(r"C:\VoiceAssistantCore\models")
    .resolve(model.id())?;
let keywords = std::iter::once(config.wake_word.keyword.as_str())
    .chain(config.wake_word.aliases.iter().map(String::as_str));
let mut detector = SherpaWakeWordDetector::new_for_model_with_aliases(
    directory, model, keywords, config.wake_word.score,
    config.wake_word.threshold, 2, config.audio.target_sample_rate,
)?;

if let Some(hit) = detector.process(&frame) {
    println!("wake word: {} at {:.2}s", hit.keyword, hit.start_time);
}
Раздел 8

Audio API

list_input_devices возвращает AudioDeviceInfo { id, name, is_default }. default_input_device сообщает текущий Windows default endpoint. AudioInput::open(device_id, queue_capacity_frames, metrics) открывает default/выбранный input и создаёт bounded callback queue; device возвращает реально открытый endpoint.

  • source_rate — нативная частота устройства;
  • recv_timeout — Ok(Some(block)), Ok(None) по timeout либо typed error;
  • полный callback queue увеличивает audio_frames_dropped;
  • callback не делает inference, файловый I/O и тяжёлое логирование.

Утилиты:

  • record_wav записывает mono WAV с worker-side resampling;
  • read_wav_mono читает PCM/float WAV и downmix;
  • resample_linear преобразует mono sample rate. Это простой streaming-block

    • resampler; заменять его следует только после измеримого KWS/STT regression.

AudioError: Device, Stream, Disconnected, Wav. Канонический внутренний формат — finite f32, mono, 16 кГц.

rust
use std::time::Duration;
use assistant_core::{CoreMetrics, audio::{AudioInput, resample_linear}};

let input = AudioInput::open("default", 250, CoreMetrics::default())?;
let (audio_worker, mut frames) = tokio::sync::mpsc::channel::<Vec<f32>>(32);
tokio::spawn(async move {
    while let Some(frame) = frames.recv().await {
        // KWS/VAD/STT работают здесь, а не в CPAL callback.
        process_audio_frame(frame).await;
    }
});
loop {
    let Some(block) = input.recv_timeout(Duration::from_millis(100))? else {
        continue;
    };
    let mono_16khz = resample_linear(&block, input.source_rate(), 16_000);
    audio_worker.send(mono_16khz).await?; // inference выполняется вне callback
}
Раздел 9

Конфигурация schema v4

audio.device_id должен быть непустым backend ID; значение default выбирает системное input-устройство.

Неизвестные TOML-поля отклоняются. CoreConfig::load и from_toml_str мигрируют schema 1–3 → 4, затем валидируют. save_atomic пишет временный файл в том же каталоге и заменяет destination с write-through. validate_with_handlers дополнительно проверяет handler schema. inference.model выбирает STT, wake_word.model — совместимую KWS-модель; изменение модели требует перезапуска daemon. wake_word.aliases задаёт дополнительные обращения; inference.threads = 0 использует host parallelism; max_restarts и restart_backoff_ms ограничивают watchdog.

Команды требуют уникальный непустой id, хотя бы одну непустую после нормализации phrase, непустой handler и timeout 1..=300000. Нормализованные phrases не могут пересекаться между командами.

RiskLevel: low, medium, high. При включённой policy подтверждение нужно, если requires_confirmation = true или risk high. При confirmations_enabled = false подтверждения полностью отключены.

AppPaths::discover использует:

text
%LOCALAPPDATA%\VoiceAssistantCore\
├── assistant.toml
├── models\

ensure_directories создаёт каталоги. Параметры можно переопределить аргументами daemon/CLI. ApplyConfig использует RuntimeUpdate и меняет только затронутые компоненты: команды, подтверждения и микрофон не пересоздают STT. Изменение IPC pipe требует перезапуска.

rust
use assistant_core::{AppPaths, CoreConfig, builtin_handlers};

let paths = AppPaths::discover()?;
paths.ensure_directories()?;
let mut config = CoreConfig::load(&paths.config)?;
config.audio.vad_threshold = 0.02;

let handlers = builtin_handlers(&config.commands)?;
config.validate_with_handlers(&handlers)?;
config.save_atomic(&paths.config)?;
Раздел 10

Model API

ALPHACEP_MODELS содержит семь allowlisted репозиториев с фиксированными commit SHA, языком, online/offline режимом и точными путями ONNX-файлов. model_spec(id) отклоняет репозитории вне каталога. Stock source:

  • repo alphacep/vosk-model-streaming-ru;
  • revision 83bbf6f40059480e96251be8aed3d32bc7c80c33;
  • runtime sherpa-onnx, language ru, 16 кГц, Apache-2.0.

ModelManager:

МетодРезультат
new(root)создаёт manager без I/O
install(model_id)устанавливает либо возвращает verified pinned revision
install_with_controlто же с AtomicBool cancel и progress callback

rust
use assistant_core::models::{ALPHACEP_MODELS, ModelManager};

let manager = ModelManager::new(r"C:\VoiceAssistantCore\models");
for model in ALPHACEP_MODELS {
    println!("{} {:?} {}", model.id(), model.mode(), model.language());
}

let directory = manager.install("alphacep/vosk-model-small-ru")?;
let manifest = manager.verify(&directory)?;
println!("{} {}", manifest.model_id, manifest.revision);

До сети установка проверяет минимум 256 МиБ свободного места и возможность write/rename. Затем она копирует только файлы выбранного ModelSpec, создаёт ModelManifest, проверяет temporary directory и активирует rename. Повреждённая установка помещается в quarantine и восстанавливается при неудачной замене. Remote scripts не выполняются.

ModelStatus: missing, installing, loading, ready, failed, cancelled. IPC запускается до blocking-загрузки STT, поэтому GUI видит Starting, текущий процент и ModelLoadProgress; shutdown и cancel отменяют загрузку кооперативно. ModelError: Io, Hub, Manifest, Verification, Cancelled.

Раздел 11

IPC wire protocol v4

Transport — \\.\pipe\<pipe_name>. Сервер:

  • запрещает remote clients;
  • применяет DACL owner/SYSTEM/Administrators;
  • использует Named Pipe first-instance и process-lifetime named mutex;
  • допускает до 16 concurrent pipe instances;
  • ограничивает frame до 1 МиБ;
  • применяет timeout к чтению и записи.

list_handlers возвращает handlers { handlers } со стабильными именами и required/optional allowlists. HealthSnapshot.components содержит ComponentHealth для audio, STT, runtime, model и IPC.

HealthSnapshot.active_audio_device содержит реально открытый input endpoint. При audio.device_id = "default" daemon автоматически переоткрывает поток после смены Windows default input. Если явно выбранное устройство исчезает, daemon временно открывает default, публикует audio_device_fallback и возвращается к выбранному устройству после его появления.

Ошибка: error { code, message }. Коды: invalid_request, protocol_version, configuration, audio, model, runtime_busy, confirmation, internal.

rust
use std::time::Duration;
use assistant_core::{CoreIpcClient, CoreRequest, CoreResponse};

# async fn example() -> Result<(), Box<dyn std::error::Error>> {
let client = CoreIpcClient::new("voice-assistant-core", Duration::from_secs(5))?;
if let CoreResponse::Health { health } =
    client.request(CoreRequest::GetHealth).await?
{
    println!("{health:?}");
}
let mut events = client.subscribe().await?;
while let Ok(event) = events.next().await {
    println!("{event:?}");
}
# Ok(()) }

CoreIpcClient::request использует новое соединение и повторяет connect до timeout. subscribe открывает отдельное event-only соединение. IpcClientError: Io, Protocol, Server { code, message }, UnexpectedResponse.

Для собственного сервера доступны serve_named_pipe, RequestHandler и ResponseFuture. encode/decode работают только с JSON envelope; length prefix добавляет transport.

rust

match handle.begin_capture().await {
    Ok(()) => {}
    Err(error) if error.code() == CoreErrorCode::Busy => {

}
Раздел 13

Метрики

CoreMetrics безопасно клонируется и использует atomics. Producers вызывают методы audio_queued/dequeued/dropped/reconnected, stt_queued/dequeued/restarted/faulted, recoverable_error, command_completed, observe_kws/stt/handler. snapshot возвращает:

  • текущую/максимальную глубину audio и STT очередей;
  • dropped audio frames, reconnects, recoverable errors, completed commands;
  • STT worker restarts и exhausted restart budgets;
  • last/max latency KWS (µs), STT и handler (ms);
  • process_working_set_bytes;
  • накопленный process_cpu_time_ms.

Process metrics равны нулю на неподдерживаемой платформе или при ошибке OS API. Счётчики монотонны до перезапуска процесса, кроме текущей глубины очереди.

rust
use assistant_core::CoreMetrics;

let metrics = CoreMetrics::default();
let worker_metrics = metrics.clone();
worker_metrics.stt_queued();
// После получения job worker обязан сбалансировать глубину очереди.
worker_metrics.stt_dequeued();
worker_metrics.observe_stt(84);

let snapshot = metrics.snapshot();
println!("STT: {} ms, max {} ms", snapshot.stt_last_ms, snapshot.stt_max_ms);

Daemon

assistant-daemon:

  • создаёт AppData/config при первом запуске;

Раздел 16

Готовность приложения

Перед показом UI:

  1. подключиться CoreIpcClient;
  2. проверить HealthSnapshot.core_version, core_api_version и protocol_version;
  3. показать last_error, если он есть;
  4. если model_ready = false, предложить InstallModel;
  5. разрешать voice controls только при audio_ready && model_ready;
  6. открыть event subscription;
  7. после reconnect перечитать health/model/config/metrics;
  8. подтверждать только token из последнего ConfirmationRequired;
  9. перед сохранением вызвать ValidateConfig, затем ApplyConfig;
  10. завершать daemon через Shutdown, если приложение им владеет.

Для обновления конфигурации UI должен редактировать полный CoreConfig, а не частичный patch. Секреты, аудио и полный transcript по умолчанию не сохраняются.

rust
use std::time::Duration;
use assistant_core::{
    CORE_API_VERSION, PROTOCOL_VERSION, CoreIpcClient, CoreRequest, CoreResponse,
};

let client = CoreIpcClient::new("voice-assistant-core", Duration::from_secs(5))?;
let response = client.request(CoreRequest::GetHealth).await?;
let CoreResponse::Health { health } = response else {
    return Err("daemon вернул неожиданный ответ".into());
};
if health.core_api_version != CORE_API_VERSION
    || health.protocol_version != PROTOCOL_VERSION
{
    return Err("несовместимая версия ядра".into());
}
if let Some(error) = &health.last_error {
    eprintln!("ядро восстанавливается: {error}");
}
let voice_controls_enabled = health.audio_ready && health.model_ready;
