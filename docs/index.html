Voice Assistant Core

Voice Assistant Core 1.1.1 — локальное Windows-ядро с versioned IPC и стабильным Rust extension API v2. GUI, аудио, inference и типизированные команды разделены явными границами.

Открыть опубликованный Rustdoc. Локально после cargo doc --workspace --all-features --no-deps он находится в target/doc/assistant_core/index.html.

Полный справочник API содержит все публичные модули, методы runtime, состояния, события, IPC request/response, параметры конфигурации, adapters, модели, метрики и CLI.

Быстрый старт

Для обычного использования скачайте Windows x64 ZIP из GitHub Releases и распакуйте его. Архив содержит готовые daemon, CLI, пример конфигурации и необходимые runtime-DLL; Rust и Cargo не требуются.

.\assistant-daemon.exe
.\assistant-cli.exe status

Для разработки самого ядра используйте сборку из исходников:

cargo run -p assistant-cli -- models install
cargo run -p assistant-daemon
cargo run -p assistant-cli -- status

Конфигурация, модели и логи по умолчанию находятся в %LOCALAPPDATA%\VoiceAssistantCore. Daemon запускается и без модели; установка доступна после запуска через IPC.

Архитектура

GUI / CLI
    → Named Pipe protocol v3
    → Runtime task
    → Audio / KWS / VAD / STT / Commands

Audio callback выполняет только преобразование кадров и неблокирующую запись в bounded-очередь. KWS, STT, файловые операции и handlers работают вне callback. Текущие состояние и health читаются без ожидания inference.

Extension API команд

#[async_trait]
impl CommandHandler for Mute {
    fn schema(&self) -> HandlerSchema {
        HandlerSchema::new(
            "mute",
            std::iter::empty::<&str>(),
            std::iter::empty::<&str>(),
        )
    }

    async fn execute(&self, parameters: &CommandParameters)
        -> Result<CommandResult, CoreError> {
        Ok(CommandResult { message: "muted".into() })
    }
}

let mut handlers = HandlerRegistry::new();
handlers.register(Arc::new(Mute))?;

Schema задаёт имя и allowlist параметров. Registry отклоняет дубликаты, неизвестные, пропущенные и лишние параметры до запуска runtime. Распознанный текст не передаётся в shell.

IPC protocol v3

\\.\pipe\voice-assistant-core, local-only DACL, один daemon, JSON envelope с protocol_version и лимитом 1 МиБ.

API включает health/status/config/metrics/audio devices, validate/apply config, status/install/cancel/verify model, suspend/resume, begin/end capture, submit text, confirm/cancel, events и shutdown. begin_capture включает push-to-talk без wake word; end_capture отправляет достаточно длинную запись в STT. submit_text принимает до 4096 байт и использует тот же command matching, risk policy и confirmation flow. Подтверждение адресуется одноразовым confirmation_id. Ошибки имеют типизированный IpcErrorCode.

IPC начинает обслуживать GUI до загрузки STT: состояние остаётся Starting, а ModelStatus::Loading и ModelLoadProgress сообщают этап и процент загрузки.

GUI получает audio_level { rms } не чаще 10 раз в секунду и transcript_unavailable { reason } с причинами wake_word_not_detected, too_short, silence или model_unavailable. Пустой audio.device_id отклоняется.

Для audio.device_id = "default" daemon автоматически переоткрывает поток при смене Windows input endpoint. HealthSnapshot.active_audio_device показывает активный endpoint, а событие AudioDeviceChanged сообщает его смену или временную недоступность.

Исчезнувший явно выбранный endpoint временно заменяется системным default; отдельное событие AudioDeviceFallback содержит исходный ID и фактически открытое устройство. После возвращения выбранного endpoint worker автоматически открывает его снова.

Конфигурация

Текущая schema — 2; schema 1 мигрируется автоматически. Изменение проверяется вместе с зарегистрированными handlers и сохраняется атомарно. Runtime дифференциально меняет только затронутые компоненты; команды, подтверждения и микрофон не перезагружают STT. Настройки pipe применяются после перезапуска.

policy.confirmations_enabled = false полностью отключает подтверждения, включая high-risk команды. Это явное снижение защиты.

Модели

Установка использует фиксированный commit SHA, allowlist файлов и SHA-256 manifest. Прогресс и отмена установки и blocking-загрузки STT доступны через IPC. Активация атомарна; неудачная переустановка не уничтожает прежнюю ревизию.

Диагностика и готовность

cargo run -p assistant-cli -- evaluate command.wav
cargo run -p assistant-cli -- soak --seconds 3600
cargo test --workspace --all-features
$env:RUSTDOCFLAGS="-D warnings"
cargo doc --workspace --all-features --no-deps

cargo test --workspace --all-features включает автоматический процессный E2E-тест: запускает настоящий assistant-daemon, подключает CoreIpcClient, проверяет health, suspend/resume и удалённый shutdown. MSVC-сборка всего workspace использует единый статический CRT, совместимый со статической Windows-библиотекой sherpa-onnx.

Метрики содержат переполнение и глубину очередей, reconnect, задержки KWS/STT/handler, CPU time и working set. Реальный WAV не хранится в Git; повторяемый ignored-тест описан в README.

Ручная проверка device switching: запустите daemon с audio.device_id = "default", подпишитесь на events, смените default-микрофон в Windows и убедитесь, что приходит audio_device_changed, а get_health показывает новый endpoint.
