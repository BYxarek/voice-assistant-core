Voice Assistant Core

Voice Assistant Core 1.0.0 — локальное Windows-ядро с versioned IPC и стабильным Rust extension API v1. GUI, аудио, inference и типизированные команды разделены явными границами.

Открыть опубликованный Rustdoc. Локально после cargo doc --workspace --all-features --no-deps он находится в target/doc/assistant_core/index.html.

Полный справочник API содержит все публичные модули, методы runtime, состояния, события, IPC request/response, параметры конфигурации, adapters, модели, метрики и CLI.

Быстрый старт

cargo run -p assistant-cli -- models install
cargo run -p assistant-daemon
cargo run -p assistant-cli -- status

Конфигурация, модели и логи по умолчанию находятся в %LOCALAPPDATA%\VoiceAssistantCore. Daemon запускается и без модели; установка доступна после запуска через IPC.

Архитектура

GUI / CLI
    → Named Pipe protocol v1
    → Runtime task
    → Audio / KWS / VAD / STT / Commands

Audio callback выполняет только преобразование кадров и неблокирующую запись в bounded-очередь. KWS, STT, файловые операции и handlers работают вне callback. Текущие состояние и health читаются без ожидания inference.

Extension API команд

#[async_trait]
impl CommandHandler for Mute {
    fn schema(&self) -> HandlerSchema {
        HandlerSchema::new(
            "mute",
            std::iter::empty::<&str>(),
            std::iter::empty::<&str>(),
        )
    }

    async fn execute(&self, parameters: &CommandParameters)
        -> Result<CommandResult, CoreError> {
        Ok(CommandResult { message: "muted".into() })
    }
}

let mut handlers = HandlerRegistry::new();
handlers.register(Arc::new(Mute))?;

Schema задаёт имя и allowlist параметров. Registry отклоняет дубликаты, неизвестные, пропущенные и лишние параметры до запуска runtime. Распознанный текст не передаётся в shell.

IPC protocol v1

\\.\pipe\voice-assistant-core, local-only DACL, один daemon, JSON envelope с protocol_version и лимитом 1 МиБ.

API включает health/status/config/metrics/audio devices, validate/apply config, status/install/cancel/verify model, suspend/resume, confirm/cancel, events и shutdown. Подтверждение адресуется одноразовым confirmation_id. Ошибки имеют типизированный IpcErrorCode.

Конфигурация

Текущая schema — 2; schema 1 мигрируется автоматически. Изменение проверяется вместе с зарегистрированными handlers и сохраняется атомарно. Настройки pipe применяются после перезапуска.

policy.confirmations_enabled = false полностью отключает подтверждения, включая high-risk команды. Это явное снижение защиты.

Модели

Установка использует фиксированный commit SHA, allowlist файлов и SHA-256 manifest. Прогресс и отмена доступны через IPC. Активация атомарна; неудачная переустановка не уничтожает прежнюю ревизию.

Диагностика и готовность

cargo run -p assistant-cli -- evaluate command.wav
cargo run -p assistant-cli -- soak --seconds 3600
cargo test --workspace --all-features
$env:RUSTDOCFLAGS="-D warnings"
cargo doc --workspace --all-features --no-deps

cargo test --workspace --all-features включает автоматический процессный E2E-тест: запускает настоящий assistant-daemon, подключает CoreIpcClient, проверяет health, suspend/resume и удалённый shutdown. MSVC-сборка всего workspace использует единый статический CRT, совместимый со статической Windows-библиотекой sherpa-onnx.

Метрики содержат переполнение и глубину очередей, reconnect, задержки KWS/STT/handler, CPU time и working set. Реальный WAV не хранится в Git; повторяемый ignored-тест описан в README.
